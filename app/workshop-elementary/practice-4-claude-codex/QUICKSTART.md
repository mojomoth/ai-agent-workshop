# 🚀 Claude × Codex Quick Start (5분)

**목표**: 두 모델의 관점을 활용해 코드 품질을 높이기

---

## 개념: Sycophancy 극복

Claude는 **자기 코드는 좋다고 생각하는 경향**이 있습니다.

```
❌ Claude 혼자: "이 코드 좋네 ✓"
✅ Claude + Codex: "이 코드 보안 문제 있고, 성능도 나쁨"
```

**해결책**: 다른 모델(Codex)의 관점 추가

---

## Step 1: 코드 구현 (1분)

Claude에게 요청:

```
"Node.js/Python/Go에서 사용자 인증 모듈을 구현해줘.
- 요구사항: JWT 토큰 기반 인증
- 입력 검증 포함
- 에러 처리 필수"
```

Claude가 생성한 코드를 저장.

---

## Step 2: Codex 검증 (1분)

생성된 코드를 Codex에 제시:

```
"위 코드를 다음 관점에서 리뷰해줘:

1. 보안 문제 (SQL 인젝션, XSS, 입력 검증)
2. 성능 문제 (N+1 쿼리, 불필요한 복사)
3. 에러 처리 누락
4. 개선 제안 (구체적인 패치 코드 포함)"
```

---

## Step 3: Claude 수정 (2분)

Codex의 피드백을 Claude에 제시:

```
"Codex의 리뷰 피드백을 반영해서 코드를 수정해줘:

[Codex 리뷰 내용]

수정 사항:
- 보안 이슈 해결
- 성능 개선
- 에러 처리 강화"
```

---

## Step 4: Codex 최종 검증 (1분)

수정된 코드를 다시 검증:

```
"수정된 코드가 이전 리뷰 피드백을 해결했는지 확인해줘.
개선된 점과 남은 문제가 있다면 지적해줘."
```

---

## 예상 결과

### Before (Claude 혼자)
```
✅ 로직 정확함
❌ SQL 인젝션 위험
❌ 에러 처리 부족
❌ 동시성 문제
```

### After (Claude + Codex)
```
✅ 로직 정확함
✅ 파라미터 검증 추가됨
✅ 예외 처리 강화됨
✅ 트랜잭션 추가됨
```

---

## 핵심 아이디어

```
1. Claude 구현 → Codex 검증 → Claude 수정 → Codex 재검증

2. 다른 관점 = 더 나은 품질
   - Claude: 아키텍처, 정확성
   - Codex: 보안, 성능, 엣지 케이스

3. 반복 → 신뢰도 상승
   - 1 라운드: 기본 개선
   - 2 라운드: 미묘한 문제 발견
```

---

## 언제 사용할까?

### ✅ 사용해야 할 때
- 보안이 중요한 코드 (인증, 결제)
- 성능이 중요한 코드 (API, 크롤러)
- 프로덕션 코드
- 복잡한 로직

### ❌ 안 써도 될 때
- 프로토타입/실험
- 토큰 제약 있을 때
- 데드라인 촉박할 때
- 간단한 스크립트
