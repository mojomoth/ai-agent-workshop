# Claude × Codex 검증 루프 구현 가이드

## 컨셉: Sycophancy 극복

Claude는 자신의 코드를 과하게 좋게 평가하는 경향이 있습니다.
다른 모델(Codex)의 관점이 필요합니다.

## 모델 역할 분담

| 모델 | 역할 | 강점 |
|---|---|---|
| Claude | 구현 | 아키텍처, 정확한 로직 |
| Codex | 검증 | 보안, 성능, 에러 처리 |

## 루프 흐름

```
[Claude 구현]
     ↓
[Codex 검증] ← 다른 모델의 관점!
     ↓
[Claude 수정] ← 피드백 반영
     ↓
[Codex 다시 검증]
     ↓
반복 또는 통과
```

## 사용할 커맨드

### Step 1: Claude 구현
```bash
claude -p "auth 모듈 구현.
규칙:
- CLAUDE.md 컨텍스트 따를 것
- 에러 처리 포함
- 소수 버그 허용 OK"
```

### Step 2: Codex 검증
```bash
codex exec "위 코드를 다음 관점에서 리뷰:
1. 보안 (인증/인가, 입력 검증)
2. 성능 (N+1 쿼리, 불필요한 복사)
3. 에러 처리 (누락된 케이스)
4. 개선 제안 (구체적인 패치 코드 포함)"
```

### Step 3: Claude 수정
```bash
claude -p "위 Codex 리뷰 반영해서 코드 수정:
- 보안 이슈 수정
- 성능 개선
- 에러 처리 강화"
```

### Step 4: Codex 최종 검증
```bash
codex exec "수정된 코드 다시 검증. 개선됐나?"
```

## 검증 게이트 (Review Gate)

자동 품질 관리 패턴:

```
구현 완료
   ↓
자동 검증 ← 이 단계가 중요
   ↓
통과? → YES → 배포
   ↓ NO
자동 수정 요청
   ↓
다시 검증
```

## 주의사항

- 비용 ⚠️ 모델 두 개 사용 → 토큰 2배 소비
- 시간 ⚠️ 루프 반복 → 총 시간 증가
- 효과 ✅ 보안/성능 문제 감소

**언제 쓸까:**
- 보안 중요 (인증, 결제)
- 프로덕션 코드
- 성능 중요 (API, 크롤러)

**언제 안 써도 됨:**
- 시작 단계 프로토타입
- 토큰 제약 있을 때
- 데드라인 촉박할 때

## Codex 설정

```bash
# 설치 (한 번만)
claude plugin install codex

# 또는 직접 호출
codex --version  # 설치 확인
```

## 결과 예상

```
[Before Codex]
✅ 코드 "완성"
❌ SQL 인젝션 가능성
❌ 동시성 버그

[After Codex Loop]
✅ 코드 완성
✅ 입력 검증 추가
✅ 트랜잭션 추가
```
